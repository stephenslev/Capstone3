### Migration Playbook Recommendations

If the project includes a data migration component, the **cloud-migration-playbook.pdf** recommends the following:

#### 🔍 Discovery Outputs
The discovery phase should produce:
- A **system inventory**
- A **data classification summary** noting any regulated or sensitive data categories
- A **preliminary risk register** — the playbook specifically notes that engagements skipping this step are disproportionately likely to encounter unplanned schedule slippage during cutover

*(Source: Retrieval Agent — cloud-migration-playbook.pdf)*

#### 🛡️ Execution Safeguards
- Migrations should be executed in **batches** rather than as a single cutover, allowing validation checkpoints and limiting the impact of any single failure
- Each batch should be **validated against source-system checksums** before the next batch begins
- A **rollback plan should exist for every batch**, not just for the final cutover
- **Daily status updates** are recommended during active migration windows — even on days with no notable progress — to prevent client anxiety

*(Source: Retrieval Agent — cloud-migration-playbook.pdf)*
